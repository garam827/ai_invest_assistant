# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Backend modules: `drive_db.py`, `data_fetcher.py`, `signal_engine.py`, `news_fetcher.py`, `openrouter_briefing.py`, `recommendation_engine.py`, `telegram_notifier.py`, `chart_builder.py`, `config.py`. The Streamlit UI ([기능 4]) is a single page (`app.py`, no top-level `st.title` — deliberately removed) split into four `st.tabs`: **소개** (about-the-program / Tom Basso philosophy blurb + the indicator glossary table — no analysis functionality, purely reference), **대표 자산군 분석** (asset-class trend analysis across 10 tickers in 5 categories — see Architecture below), **종목 차트 (S&P 500)** (per-ticker candlestick + signal chart), and **데이터 적재** (the manual data-collection trigger — originally tab 1, moved to last position as more tabs were added). Deliberately a single page, not a multipage `pages/` app (removed by request). The all-tickers signal scan table and the chat tab are not built.

**Automation is live** ([기능 5]): GitHub Actions (`.github/workflows/collect.yml` + `recommend.yml`, chained via `workflow_run`) replaced the originally-planned GCP Cloud Run/Cloud Scheduler (abandoned over billing-account friction). `collect.yml` runs `python data_fetcher.py update` on a weekday cron; on success, `recommend.yml` runs `python recommendation_engine.py`, which generates 매수/HOLD/매도 calls for `ASSET_CLASS_TICKERS` only (not all 503 S&P 500 tickers — keeps LLM/news usage bounded) and sends Telegram notifications. The "데이터 적재" tab's button remains as a manual, on-demand alternative to the collect cron. There is no test suite or lint config yet — when one is added, update this file with the actual commands.

Setup: `pip install -r requirements.txt`, copy `.env.example` to `.env` and fill in `DRIVE_FOLDER_ID` / `GOOGLE_OAUTH_CLIENT_SECRET_PATH` / `OPENROUTER_API_KEY` / `EXA_API_KEY` (see [GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md) for the Drive OAuth setup) and optionally `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` (see [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md) — daily recommendation notifications, cron-only). `data_fetcher.py` is runnable directly: `python data_fetcher.py init` (5y backfill of S&P 500 + asset-class tickers, run once), `python data_fetcher.py update` (S&P 500 membership sync + daily append + asset-class update, the intended cron command — same as `data_fetcher.run_full_collection`), or `python data_fetcher.py sync` (S&P 500 membership reconciliation only). All 503 current S&P 500 tickers plus all `ASSET_CLASS_TICKERS` have already been backfilled into the live Drive folder. Run the UI with `streamlit run app.py`.

## What this project is

A Tom Basso-style ("Mr. Serenity") trend-following investment assistant chatbot: a rule-based, ATR-driven trend-following signal and position-sizing engine wrapped in an LLM chat interface, applied to both individual S&P 500 stocks and representative asset-class proxies (equities, crypto, precious metals, bonds, commodities). Full spec (versioned, latest first): [investment_assistant_spec.md](investment_assistant_spec.md).

## Architecture

- **Frontend / Chat UI**: Streamlit, single page (`app.py`) with `st.tabs` separating features (not a multipage `pages/` app — everything runs in one process/session so tabs share `st.cache_resource`/`st.cache_data` state directly)
- **Data source**: yfinance (Yahoo Finance API) — daily OHLCV for all S&P 500 tickers plus `data_fetcher.ASSET_CLASS_TICKERS` (10 tickers across 5 categories: 주식 `SPY`, 암호화폐 `BTC-USD`, 귀금속 `GLD`, 채권 `TLT`/`IEF`, 원자재 `DBC`/`USO`/`UNG`/`DBA`/`CPER`). News for the LLM recommendation flow comes from the **Exa search API** (`news_fetcher.fetch_ticker_news_exa`), not yfinance — see below.
- **"Database"**: Google Drive API storing one Apache Parquet file per ticker (`[Ticker].parquet`), accessed via OAuth user credentials (not a service account — the GCP project enforces `iam.disableServiceAccountKeyCreation`, see [GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md)) — see `drive_db.DriveDB`. Also stores small JSON metadata files: `_universe.json` (S&P 500 active/inactive tickers + sectors + descriptions), `_news_{YYYY-MM-DD}.json` (per-date news archive, see below), and `_recommendations_{YYYY-MM-DD}.json` (daily cron recommendation results).
- **LLM engine**: OpenRouter (default model `nvidia/nemotron-3-ultra-550b-a55b:free`, configurable via `OPENROUTER_MODEL_NAME`) — see `openrouter_briefing.py`. Switched from Vertex AI/Gemini for cost reasons (see spec changelog). The buy/hold/sell **action** itself never depends on the LLM (see Core signal & sizing logic below) — the LLM only adds narrative explanation on 매수/매도 days.
- **Infra**: GitHub Actions (`.github/workflows/collect.yml` + `recommend.yml`, chained via `workflow_run`) — see Data flow below. Originally planned as GCP Cloud Run + Cloud Scheduler, abandoned over a billing-account blocker.
- **Notifications**: Telegram (`telegram_notifier.py`), cron-only — see [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md).

### Module map

- `config.py` — all tunables/secrets, loaded from `.env`. Every other module reads from here rather than hardcoding constants.
- `drive_db.py` — `DriveDB` class: Drive OAuth user auth (browser consent on first run, cached to `token.json` thereafter), per-ticker Parquet find/download/upload, `upsert_ticker` (concat + `drop_duplicates` by Date + re-upload), plus generic `load_json`/`save_json` for small metadata files (used for the ticker universe and the news archive, see below).
- `data_fetcher.py` — S&P 500 ticker list (scraped from Wikipedia via `requests` + a browser User-Agent, since Wikipedia 403s the default urllib UA — parsed with `pd.read_html(io.StringIO(...))`), yfinance OHLCV fetch, `run_initial_ingestion` (5y backfill), `sync_universe` (reconciles S&P 500 membership changes, see Data flow below), `run_daily_update` (delta fetch + upsert for the active S&P 500 universe), `run_asset_class_update` (same delta-fetch logic, applied to the fixed `ASSET_CLASS_TICKERS` dict — independent of S&P membership), `run_full_collection` (all three, in order — what the "데이터 적재" tab and `python data_fetcher.py update` both run). `_update_one_ticker` is the shared per-ticker delta-fetch-and-upsert helper both `run_daily_update` and `run_asset_class_update` call. `ASSET_CLASS_TICKERS` is `{ticker: {"label": display_name, "category": category, "description": one_liner}}` — categories: 주식/암호화폐/귀금속/채권/원자재. `sync_universe` also builds a `{ticker: "회사명 (GICS 세부업종)"}` description map from the same Wikipedia table (no extra requests) and writes it into `_universe.json`'s `descriptions` key for all active S&P 500 tickers. CLI entry point via `if __name__ == "__main__"` with `init`/`update`/`sync` modes.
- `signal_engine.py` — pure pandas, no I/O, and ticker-agnostic (same functions work on S&P stocks or asset-class tickers). Donchian channel, Wilder ATR, Bollinger Bands (reference-only, not part of the entry/exit rules), trailing stop, volume-surge filter, position sizing, `Buy_Trigger`/`Sell_Trigger` (first-occurrence-only versions of the breakout/exit conditions, for marking entry/exit points on a chart without re-marking every day a trend stays valid), `get_mechanical_action(summary)` (deterministic 매수/HOLD/매도 from breakout/exit flags alone, no network — the sole source of truth for the action, see Core signal & sizing logic below), and `scan_for_signals` which ranks a `{ticker: df}` map by breakout+volume-surge priority (documented future feature, not yet wired into the UI).
- `news_fetcher.py` — `fetch_ticker_news_exa(ticker, ...)` is the only source (the yfinance-based `fetch_ticker_news`/`fetch_news_for_tickers` were fully superseded by this and deleted in v2.8, not kept as unused parallel code). Queries Exa's search API (`https://api.exa.ai/search`, `x-api-key` header from `config.EXA_API_KEY`) with `category: "news"`, a `"{ticker} stock news"` query, and `startPublishedDate` from `config.EXA_NEWS_LOOKBACK_DAYS` (default 7); requests `contents.summary`. Maps Exa's `author` field to `publisher`, falling back to the article URL's domain (`urlparse(link).netloc`) if missing. Raises `ValueError` if `EXA_API_KEY` isn't set. `archive_news(drive_db, ticker, news_items, date=None)`: persists news to a per-calendar-date Drive JSON file (`_news_{date}.json`, `{ticker: [news_item, ...]}`), deduped by article link (falls back to title) so re-running on the same day doesn't store duplicates.
- `openrouter_briefing.py` — calls OpenRouter's OpenAI-compatible `/chat/completions` endpoint directly via `requests` (no SDK dependency, shared `_call_chat` helper). `generate_briefing`: the "Mr. Serenity" noise-vs-signal news summary (not currently wired into the UI, but a distinct documented capability — not dead code). `generate_recommendation`: given news + a `signal_engine.get_latest_signal_summary` dict, returns `{"action": "매수"|"HOLD"|"매도", "text": ...}` — the LLM's own read of the situation, parsed from a required `추천: ...` first line (regex `_RECOMMENDATION_PATTERN`; defaults to `"HOLD"` if the model doesn't follow the format). **This action is advisory only** — `recommendation_engine` logs a warning if it disagrees with the mechanical action but always uses the mechanical one.
- `recommendation_engine.py` — shared recommendation logic used by both `app.py` (one ticker at a time, on user demand) and the cron (`recommend.yml` → `python recommendation_engine.py`, batch over `ASSET_CLASS_TICKERS`). `_is_data_fresh(raw_df)`: guards against generating a recommendation from stale data (last bar older than `config.DATA_FRESHNESS_MAX_AGE_DAYS`, default 4 days) — needed because `data_fetcher`'s per-ticker `try/except` means an overall-successful collection run can still have silently skipped individual tickers. `get_recommendation_for_ticker(drive_db, ticker)`: computes the action via `signal_engine.get_mechanical_action` (always, no network); on HOLD, returns immediately with a fixed explanation and skips news/LLM entirely; on 매수/매도, fetches news (Exa) + asks the LLM for a narrative, falling back to `_build_rule_based_explanation` (cites the exact numeric rule that fired) if either call fails — validated against a real OpenRouter 429 rate-limit response, the action is never dropped. `run_asset_class_recommendations(drive_db, tickers=None)`: batch entry point, persists results to `_recommendations_{date}.json`, and calls `telegram_notifier.notify_recommendations` if Telegram env vars are set. CLI entry point (`if __name__ == "__main__"`) is what `recommend.yml` runs.
- `chart_builder.py` — the shared Plotly figure builder (`build_ticker_chart_figure`) and `slice_to_period(signals, days)` (slices an already-`compute_signals()`'d DataFrame to a display window — callers compute signals on full history first so Donchian-100/ATR lookback isn't distorted, then slice only for display). Used by both `app.py` (browser renders Korean natively) and `telegram_notifier.py` (kaleido renders headlessly via Chromium — no CJK font on a bare Ubuntu Actions runner by default, so the figure explicitly requests `FONT_FAMILY = "Nanum Gothic, Malgun Gothic, Noto Sans CJK KR, ..."` and `recommend.yml` installs `fonts-nanum`; see Implementation constraints below).
- `telegram_notifier.py` — called only from `recommendation_engine.run_asset_class_recommendations` (cron path), never from `app.py`'s interactive per-ticker flow (every "조회" click would otherwise spam the chat). `send_message`/`send_photo`: raw `requests` calls to the Telegram Bot API (no SDK). `format_summary`: one message per day, all tickers, rendered as a monospace table (ticker/category/action/close) inside a Markdown code block — Telegram's Bot API doesn't render GFM/HTML tables in any parse_mode, so a padded-columns code block is the closest practical substitute. Columns are aligned with `_display_width`/`_pad` (`unicodedata.east_asian_width`-aware padding, since Korean 매수/HOLD/매도 mix full-width and half-width characters); action emoji are kept out of the table (client-dependent display width breaks alignment) and shown once as a legend line instead. `notify_recommendations`: sends the summary, then — for 매수/매도 tickers only (not HOLD) — builds a chart via `chart_builder`, slices to `CHART_PERIOD_DAYS = 180` (6 months; the full multi-year history compresses candles until they're unreadable in a single image), renders to PNG via `fig.to_image(...)` (kaleido), and sends it with a caption.
- `app.py` — single Streamlit page, no top-level `st.title`, four `st.tabs`. **"소개"**: an "about this program" + Tom Basso philosophy blurb (`st.expander`, expanded by default) and the indicator glossary (`st.table(INDICATOR_TABLE)`) — no analysis widgets, purely reference, shown once here (not repeated per-chart). **"대표 자산군 분석"**: category select (주식/암호화폐/귀금속/채권/원자재) lives outside an `st.form` and narrows the ticker dropdown immediately, mirroring the sector pattern in the next tab. **"종목 차트 (S&P 500)"**: sector select (from `_universe.json`'s `sectors` map) lives outside an `st.form` so it narrows the ticker dropdown immediately; ticker + period are inside the form, so the expensive Drive-load/compute/render only runs on the "조회" submit click. Both chart tabs call the shared `render_ticker_chart(ticker, period_label, subtitle, key_prefix)` — computes signals once, builds the display slice via `chart_builder.slice_to_period` and the figure via `chart_builder.build_ticker_chart_figure`, adds Buy/Sell trigger markers (▲/▼) baked into the figure, and renders an LLM recommendation section (`get_recommendation`, a thin `st.cache_data(ttl=86400)` wrapper around `recommendation_engine.get_recommendation_for_ticker`, cached by `(ticker, latest_date)` so it isn't re-called on every rerun — **important**: `st.tabs` bodies all execute every rerun regardless of which tab is visually active, so without this cache the LLM/news calls would be re-hit on every unrelated interaction anywhere in the app) that also renders the source news articles as cards (title/link, publisher/timestamp, summary). **"데이터 적재"**: one button runs `data_fetcher.run_full_collection`, streaming log output via a custom `logging.Handler`, then clears the `get_universe`/`load_ticker_data` caches so the chart tabs reflect fresh data immediately. `DriveDB` is `st.cache_resource`; ticker list and per-ticker data are `st.cache_data(ttl=3600)`. Selections persist in `st.session_state` (namespaced per tab: `selected_asset_*` / `selected_sp500_*`) across reruns — avoid `st.stop()` inside a tab body, it would also cut off tabs defined later in the script; use if/else nesting instead.

### Data flow

1. **`collect.yml`** (weekday cron, `workflow_dispatch` also available) runs `data_fetcher.py update` (== `run_full_collection`) after market close.
2. `sync_universe` runs first: diffs the live S&P 500 list (Wikipedia's GICS Sector table, excluding `ASSET_CLASS_TICKERS` from the "stored" side of the diff — they're never S&P 500 constituents, so without the exclusion they'd get flagged as removed every run) against Drive's stored tickers. New entrants get backfilled via `run_initial_ingestion`; removed entrants keep their Parquet file (history preserved) but drop out of the active list. The result is written to `_universe.json` in the Drive folder (`{"active_tickers": [...], "inactive_tickers": [...], "sectors": {...}, "descriptions": {...}, "synced_at": ...}`) via `DriveDB.save_json`.
3. `run_daily_update` fetches only the tickers in `_universe.json`'s `active_tickers` (falling back to `DriveDB.list_tickers()` only if the universe file doesn't exist yet); `run_asset_class_update` does the same for the fixed asset-class set. Both use `_update_one_ticker`: new OHLCV rows are appended to each ticker's Parquet file via `DriveDB.upsert_ticker` (dedup by date, lookback anchored to that ticker's own last stored date — not a fixed "last N days from today" — so it self-heals if a run is skipped).
4. **`recommend.yml`** runs next, chained via `workflow_run` (only if `collect.yml` succeeded) or manually via `workflow_dispatch`. Runs `recommendation_engine.py`, which for each of `ASSET_CLASS_TICKERS` (not the full S&P 500): checks `_is_data_fresh` (skip if stale), computes signals + `signal_engine.get_mechanical_action` (deterministic action, no network), skips news/LLM entirely on HOLD, and on 매수/매도 fetches Exa news + asks the LLM for a narrative (falling back to `_build_rule_based_explanation` on failure). Results are saved to `_recommendations_{date}.json` and sent to Telegram (`telegram_notifier.notify_recommendations` — summary text for all tickers, chart image for 매수/매도 tickers only, 6-month window).
5. In the Streamlit chart tabs (interactive, on-demand, one ticker at a time — no Telegram), `render_ticker_chart` calls `get_recommendation` → `recommendation_engine.get_recommendation_for_ticker`, the same function the cron uses, cached by `(ticker, latest_date)`.
6. Any new tab/feature should source its ticker universe from `_universe.json`'s `active_tickers`/`sectors`/`descriptions`, not a raw `DriveDB.list_tickers()`, so delisted/removed tickers don't show up in signal results (see the "종목 차트" tab for the established pattern).

### Core signal & sizing logic (must match spec exactly)

- **Donchian Channel**: dual window, 20-day and 100-day highs/lows, computed excluding today (`shift(1)`) so a breakout is measurable.
  - Buy signal: close breaks above the N-day high.
  - Exit signal: close breaks below the trailing stop line.
- **ATR**: 14-day Wilder's smoothing (`ewm(alpha=1/window, adjust=False)` in `signal_engine.calculate_atr`).
- **Bollinger Bands**: 20-day SMA ± 2 std dev — reference-only overlay, not part of the entry/exit rules.
- **Trailing stop**: `highest_high_over_window - 3 * ATR`.
- **Position sizing**: `shares = (account_equity * risk_pct) // (3 * ATR)`, risk_pct defaults to 1% (`config.DEFAULT_RISK_PCT`).
- **False-breakout filter**: only surface a breakout if that day's volume ≥ 1.5x the 20-day average volume (`config.VOLUME_SURGE_MULTIPLIER`).
- **Asset-class trend following**: the same rules apply unmodified to `ASSET_CLASS_TICKERS` — raw indices (e.g. `^GSPC`) or yield quotes (e.g. `^TNX`) aren't directly tradable and often lack reliable volume data, hence tradable ETF/spot proxies (SPY for the S&P 500 itself, BTC-USD for bitcoin, GLD for gold, TLT/IEF for long/mid-term Treasuries, DBC/USO/UNG/DBA/CPER for broad/oil/nat-gas/agriculture/copper commodities).
- **Mechanical action decoupling**: the 매수/HOLD/매도 call is always `signal_engine.get_mechanical_action(summary)` — pure rules, no network. The LLM (`openrouter_briefing.generate_recommendation`) only adds narrative on 매수/매도 days and is advisory-only; `recommendation_engine.get_recommendation_for_ticker` ignores the LLM's own action if it disagrees, and falls back to `_build_rule_based_explanation` if the LLM/news call fails outright, so the action is never lost or downgraded to HOLD by a network failure.

## Implementation constraints from the spec

- Throttle yfinance calls with `config.YFINANCE_REQUEST_DELAY_SEC` (default 0.5s) between tickers to avoid rate-limit blocks — already applied in `data_fetcher.py`'s loops.
- Avoid re-downloading full Parquet files from Google Drive on every read for frequently-accessed data — use Streamlit's `st.cache_data` (see `app.py`).
- The "Mr. Serenity" prompts (`openrouter_briefing.SYSTEM_PROMPT`, `RECOMMENDATION_SYSTEM_PROMPT`) must strip short-term noise/sentiment from news and judge only whether it reinforces or is irrelevant to the long-term trend / mechanical signal state — do not reword these casually, they're copied verbatim from the spec.
- Never let `sync_universe`'s S&P 500 membership diff include `data_fetcher.ASSET_CLASS_TICKERS` — they must stay excluded from the "stored" side of the diff or they'll be misclassified as delisted every run.
- Keep LLM calls behind a cache keyed on data freshness (e.g. `(ticker, latest_date)`), not just a short TTL — `st.tabs` executes every tab body on every rerun, so an uncached or short-TTL LLM call gets hit far more often than the user's actual clicks would suggest.
- The recommendation flow requires `EXA_API_KEY` (news) in addition to `OPENROUTER_API_KEY` (LLM) — both raise a clear `ValueError` if unset, don't silently fall back.
- A headless-Chromium chart render (kaleido, used by `telegram_notifier.py`) needs a CJK font installed on the runner (`fonts-nanum` in `recommend.yml`) plus an explicit `font family` on the Plotly figure (`chart_builder.FONT_FAMILY`) — otherwise Korean text silently renders as blank/tofu glyphs on a bare Ubuntu Actions runner (not reproducible locally on a machine that already has the font installed).
- Never let a news/LLM failure drop or downgrade the mechanical 매수/매도 action — fall back to a rule-based explanation (`recommendation_engine._build_rule_based_explanation`) instead.
