## What this project is

A Tom Basso-style ("Mr. Serenity") trend-following investment assistant chatbot: a rule-based, ATR-driven trend-following signal and position-sizing engine wrapped in an LLM chat interface, applied to both individual S&P 500 stocks and representative asset-class proxies (equities, crypto, precious metals, bonds, commodities). Full spec (versioned, latest first): [investment_assistant_spec.md](investment_assistant_spec.md).

## Architecture

- **Frontend / Chat UI**: Streamlit, single page (`app.py`) with `st.tabs` separating features (not a multipage `pages/` app — everything runs in one process/session so tabs share `st.cache_resource`/`st.cache_data` state directly)
- **Data source**: yfinance (Yahoo Finance API) — daily OHLCV for all S&P 500 tickers plus `data_fetcher.ASSET_CLASS_TICKERS` (10 tickers across 5 categories: 주식 `SPY`, 암호화폐 `BTC-USD`, 귀금속 `GLD`, 채권 `TLT`/`IEF`, 원자재 `DBC`/`USO`/`UNG`/`DBA`/`CPER`). News for the LLM recommendation flow comes from the **Exa search API** (`news_fetcher.fetch_ticker_news_exa`), not yfinance — see below.
- **"Database"**: Google Drive API storing one Apache Parquet file per ticker (`[Ticker].parquet`), accessed via OAuth user credentials (not a service account — the GCP project enforces `iam.disableServiceAccountKeyCreation`, see [GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md)) — see `drive_db.DriveDB`. Also stores small JSON metadata files: `_universe.json` (S&P 500 active/inactive tickers + sectors) and `_news_{YYYY-MM-DD}.json` (per-date news archive, see below).
- **LLM engine**: OpenRouter (default model `nvidia/nemotron-3-ultra-550b-a55b:free`, configurable via `OPENROUTER_MODEL_NAME`) — see `openrouter_briefing.py`. Switched from Vertex AI/Gemini for cost reasons (see spec changelog).
- **Infra**: GCP Cloud Run (Docker) + Cloud Scheduler triggers a daily post-market-close data collection job (not yet containerized)

### Module map

- `config.py` — all tunables/secrets, loaded from `.env`. Every other module reads from here rather than hardcoding constants.
- `drive_db.py` — `DriveDB` class: Drive OAuth user auth (browser consent on first run, cached to `token.json` thereafter), per-ticker Parquet find/download/upload, `upsert_ticker` (concat + `drop_duplicates` by Date + re-upload), plus generic `load_json`/`save_json` for small metadata files (used for the ticker universe and the news archive, see below).
- `data_fetcher.py` — S&P 500 ticker list (scraped from Wikipedia via `requests` + a browser User-Agent, since Wikipedia 403s the default urllib UA — parsed with `pd.read_html(io.StringIO(...))`), yfinance OHLCV fetch, `run_initial_ingestion` (5y backfill), `sync_universe` (reconciles S&P 500 membership changes, see Data flow below), `run_daily_update` (delta fetch + upsert for the active S&P 500 universe), `run_asset_class_update` (same delta-fetch logic, applied to the fixed `ASSET_CLASS_TICKERS` dict — independent of S&P membership), `run_full_collection` (all three, in order — what the "데이터 적재" tab and `python data_fetcher.py update` both run). `_update_one_ticker` is the shared per-ticker delta-fetch-and-upsert helper both `run_daily_update` and `run_asset_class_update` call. `ASSET_CLASS_TICKERS` is `{ticker: {"label": display_name, "category": category}}` — categories: 주식/암호화폐/귀금속/채권/원자재. CLI entry point via `if __name__ == "__main__"` with `init`/`update`/`sync` modes.
- `signal_engine.py` — pure pandas, no I/O, and ticker-agnostic (same functions work on S&P stocks or asset-class tickers). Donchian channel, Wilder ATR, Bollinger Bands (reference-only, not part of the entry/exit rules), trailing stop, volume-surge filter, position sizing, `Buy_Trigger`/`Sell_Trigger` (first-occurrence-only versions of the breakout/exit conditions, for marking entry/exit points on a chart without re-marking every day a trend stays valid), and `scan_for_signals` which ranks a `{ticker: df}` map by breakout+volume-surge priority.
- `news_fetcher.py` — `fetch_ticker_news_exa(ticker, ...)`: **this is the one the app actually calls**. Queries Exa's search API (`https://api.exa.ai/search`, `x-api-key` header from `config.EXA_API_KEY`) with `category: "news"`, a `"{ticker} stock news"` query, and `startPublishedDate` from `config.EXA_NEWS_LOOKBACK_DAYS` (default 7); requests `contents.summary`. Maps Exa's `author` field to `publisher`, falling back to the article URL's domain (`urlparse(link).netloc`) if missing. Raises `ValueError` if `EXA_API_KEY` isn't set. `fetch_ticker_news`: the original yfinance-based fetcher (`yfinance.Ticker(ticker).news`, filtered to `contentType == "STORY"`) — still defined, kept for reference, but no longer called by `app.py`. `archive_news(drive_db, ticker, news_items, date=None)`: persists whichever source's news to a per-calendar-date Drive JSON file (`_news_{date}.json`, `{ticker: [news_item, ...]}`), deduped by article link (falls back to title) so re-running on the same day doesn't store duplicates. Both fetchers return the same shape (`title`/`summary`/`publisher`/`link`/`published_at`), so `archive_news`, the news cards, and `generate_recommendation` don't care which one produced the data.
- `openrouter_briefing.py` — calls OpenRouter's OpenAI-compatible `/chat/completions` endpoint directly via `requests` (no SDK dependency, shared `_call_chat` helper). `generate_briefing`: the "Mr. Serenity" noise-vs-signal news summary (not currently wired into the UI). `generate_recommendation`: given news + a `signal_engine.get_latest_signal_summary` dict, returns `{"action": "매수"|"HOLD"|"매도", "text": ...}` — a mechanical buy/hold/sell call per Basso's rules, parsed from a required `추천: ...` first line (regex `_RECOMMENDATION_PATTERN`; defaults to `"HOLD"` if the model doesn't follow the format).
- `app.py` — single Streamlit page, no top-level `st.title`, four `st.tabs`. **"소개"**: an "about this program" + Tom Basso philosophy blurb (`st.expander`, expanded by default) and the indicator glossary (`st.table(INDICATOR_TABLE)`) — no analysis widgets, purely reference, shown once here (not repeated per-chart). **"대표 자산군 분석"**: category select (주식/암호화폐/귀금속/채권/원자재) lives outside an `st.form` and narrows the ticker dropdown immediately, mirroring the sector pattern in the next tab. **"종목 차트 (S&P 500)"**: sector select (from `_universe.json`'s `sectors` map) lives outside an `st.form` so it narrows the ticker dropdown immediately; ticker + period are inside the form, so the expensive Drive-load/compute/render only runs on the "조회" submit click. Both chart tabs call the shared `render_ticker_chart(ticker, period_label, subtitle, key_prefix)` — candlestick + Bollinger/Donchian/trailing-stop overlays, Buy/Sell trigger markers (▲/▼), volume/ATR subplots, and an LLM recommendation section (`get_recommendation`, cached by `(ticker, latest_date)` with `ttl=86400` so it isn't re-called on every rerun — **important**: `st.tabs` bodies all execute every rerun regardless of which tab is visually active, so without this cache the LLM/news calls would be re-hit on every unrelated interaction anywhere in the app) that also renders the source news articles as cards (title/link, publisher/timestamp, summary) and archives them via `news_fetcher.archive_news`. **"데이터 적재"**: one button runs `data_fetcher.run_full_collection`, streaming log output via a custom `logging.Handler`, then clears the `get_universe`/`load_ticker_data` caches so the chart tabs reflect fresh data immediately. `DriveDB` is `st.cache_resource`; ticker list and per-ticker data are `st.cache_data(ttl=3600)`. Selections persist in `st.session_state` (namespaced per tab: `selected_asset_*` / `selected_sp500_*`) across reruns — avoid `st.stop()` inside a tab body, it would also cut off tabs defined later in the script; use if/else nesting instead.

### Data flow

1. Cloud Scheduler hits a Cloud Run endpoint after market close to run `data_fetcher.py update` (== `run_full_collection`).
2. `sync_universe` runs first: diffs the live S&P 500 list (Wikipedia's GICS Sector table, excluding `ASSET_CLASS_TICKERS` from the "stored" side of the diff — they're never S&P 500 constituents, so without the exclusion they'd get flagged as removed every run) against Drive's stored tickers. New entrants get backfilled via `run_initial_ingestion`; removed entrants keep their Parquet file (history preserved) but drop out of the active list. The result is written to `_universe.json` in the Drive folder (`{"active_tickers": [...], "inactive_tickers": [...], "sectors": {...}, "synced_at": ...}`) via `DriveDB.save_json`.
3. `run_daily_update` fetches only the tickers in `_universe.json`'s `active_tickers` (falling back to `DriveDB.list_tickers()` only if the universe file doesn't exist yet); `run_asset_class_update` does the same for the fixed asset-class set. Both use `_update_one_ticker`: new OHLCV rows are appended to each ticker's Parquet file via `DriveDB.upsert_ticker` (dedup by date, lookback anchored to that ticker's own last stored date — not a fixed "last N days from today" — so it self-heals if a run is skipped).
4. `signal_engine.compute_signals` recomputes Donchian Channel, ATR, Bollinger Bands, trailing stop, volume-surge flag, and Buy/Sell triggers from the accumulated per-ticker data — identically for S&P stocks and asset-class tickers.
5. In the Streamlit chart tabs, `news_fetcher.fetch_ticker_news_exa` pulls the ticker's recent news via Exa, `news_fetcher.archive_news` persists them to that day's `_news_{date}.json`, and `openrouter_briefing.generate_recommendation` combines the news with the current signal state into a cached 매수/HOLD/매도 call; `generate_briefing` (noise-vs-signal summary, no buy/hold/sell call) is also available but not yet wired into a UI tab.
6. Any new tab/feature should source its ticker universe from `_universe.json`'s `active_tickers`/`sectors`, not a raw `DriveDB.list_tickers()`, so delisted/removed tickers don't show up in signal results (see the "종목 차트" tab for the established pattern).

### Core signal & sizing logic (must match spec exactly)

- **Donchian Channel**: dual window, 20-day and 100-day highs/lows, computed excluding today (`shift(1)`) so a breakout is measurable.
  - Buy signal: close breaks above the N-day high.
  - Exit signal: close breaks below the trailing stop line.
- **ATR**: 14-day Wilder's smoothing (`ewm(alpha=1/window, adjust=False)` in `signal_engine.calculate_atr`).
- **Bollinger Bands**: 20-day SMA ± 2 std dev — reference-only overlay, not part of the entry/exit rules.
- **Trailing stop**: `highest_high_over_window - 3 * ATR`.
- **Position sizing**: `shares = (account_equity * risk_pct) // (3 * ATR)`, risk_pct defaults to 1% (`config.DEFAULT_RISK_PCT`).
- **False-breakout filter**: only surface a breakout if that day's volume ≥ 1.5x the 20-day average volume (`config.VOLUME_SURGE_MULTIPLIER`).
- **Asset-class trend following**: the same rules apply unmodified to `ASSET_CLASS_TICKERS` — raw indices (e.g. `^GSPC`) or yield quotes (e.g. `^TNX`) aren't directly tradable and often lack reliable volume data, hence tradable ETF/spot proxies (SPY for the S&P 500 itself, BTC-USD for bitcoin, GLD for gold, TLT/IEF for long/mid-term Treasuries, DBC/USO/UNG/DBA/CPER for broad/oil/nat-gas/agriculture/copper commodities).

## Implementation constraints from the spec

- Throttle yfinance calls with `config.YFINANCE_REQUEST_DELAY_SEC` (default 0.5s) between tickers to avoid rate-limit blocks — already applied in `data_fetcher.py`'s loops.
- Avoid re-downloading full Parquet files from Google Drive on every read for frequently-accessed data — use Streamlit's `st.cache_data` (see `app.py`).
- The "Mr. Serenity" prompts (`openrouter_briefing.SYSTEM_PROMPT`, `RECOMMENDATION_SYSTEM_PROMPT`) must strip short-term noise/sentiment from news and judge only whether it reinforces or is irrelevant to the long-term trend / mechanical signal state — do not reword these casually, they're copied verbatim from the spec.
- Never let `sync_universe`'s S&P 500 membership diff include `data_fetcher.ASSET_CLASS_TICKERS` — they must stay excluded from the "stored" side of the diff or they'll be misclassified as delisted every run.
- Keep LLM calls behind a cache keyed on data freshness (e.g. `(ticker, latest_date)`), not just a short TTL — `st.tabs` executes every tab body on every rerun, so an uncached or short-TTL LLM call gets hit far more often than the user's actual clicks would suggest.
- The recommendation flow requires `EXA_API_KEY` (news) in addition to `OPENROUTER_API_KEY` (LLM) — both raise a clear `ValueError` if unset, don't silently fall back.
