# Drive 병렬 수집 명세

버전: v1.0 / 2026-09-18 / 프로젝트 v3.67

## 목적과 범위

Yahoo 조회의 동시 요청 수를 늘리지 않고 Google Drive의 대기 시간을 겹쳐 일일 수집을 개선한다.
`run_daily_update`, `run_asset_class_update`에 적용한다. 유니버스 동기화와 초기 전체 이력 수집은 순차 경로를 유지하며 초기 수집도 공통 Yahoo 제한을 사용한다.
리포트 생성·발송, 복구 작업, 공개 Streamlit의 읽기 전용 동작은 변경하지 않는다.

## 동작

각 작업자는 `Drive 읽기 → Yahoo 조회 → 유효성 검사 → 병합 → Drive 저장`을 수행한다.
스레드 풀에서 작업자마다 별도 Drive 클라이언트를 한 번 생성해 재사용하고, 배치 종료 후 닫는다.
입력 티커는 중복 제거한다. 제출 대기 중인 작업은 티커 문자열만 보유하며 가격 데이터는 실행 중인 작업에서 읽는다.
같은 프로세스·Drive 폴더·종목의 전체 갱신을 종목별 RLock으로 보호한다. 같은 연결의 HTTP 요청은 연결별 잠금으로 보호한다.
OAuth 초기 로드·갱신·원자적 토큰 저장과 모의투자 보호는 유지한다.
[Google API 클라이언트의 스레드 안전성](https://googleapis.github.io/google-api-python-client/docs/thread_safety.html)

Yahoo 요청은 공통 잠금 안에서 실행한다. 이전 요청 종료 후 설정된 간격을 기다리며 동시에 실행되는 요청은 1개다.
요청 시간 제한은 30초다. `YFRateLimitError` 발생 시 다음 Yahoo 요청부터 공유 대기를 적용한다.
연속 제한 오류는 기본 60 → 120 → 240 → 480초로 대기가 늘어나며 정상 응답 후 초기화한다.
이 제한은 안전한 호출량을 보장하지 않는다. Yahoo의 실제 제한에 맞춰 설정을 조정한다.

## 검증과 재시도

- 검증된 새 데이터와 기존 이력을 병합하고 중복 날짜는 새 값으로 교체한다. 동일 종목 트랜잭션 안에서 저장하므로 Drive 중복 다운로드를 피한다.
- 빈 응답은 실패다. 가격·거래량 오류는 날짜 및 잘못된 필드·값을 최대 5행까지 기록한다.
- 기존 불량 OHLCV 즉시 재조회는 최대 3회 유지한다. 이후 배치 라운드에서 실패 종목만 지연 재시도한다.
- 읽기·Yahoo 조회(공유 대기 포함)·병합 및 저장·전체 시간을 로그와 결과에 기록한다.
- 모든 future 완료 후 성공·실패·시도 횟수를 집계한다. 클라이언트 생성 실패와 저장 실패도 종목 실패로 집계한다.
- 개별 주식의 최종 실패는 기존 운영 정책대로 경고·결과에 남기고 대표 자산군 수집을 진행한다. 대표 자산군 최종 실패는 예외를 발생시켜 후속 추천·발행을 차단한다.
- Streamlit 작업 스레드에서는 로그만 적재한다. UI 스레드의 진행 로그 및 종료 시점에 화면을 갱신한다.

## 설정

| 환경변수 | 기본값 | 의미 |
| --- | --- | --- |
| COLLECTION_WORKERS | 3 | Drive 작업자 수, 1~8. 1은 기존 연결로 순차 실행 |
| YFINANCE_REQUEST_DELAY_SEC | 0.5 | Yahoo 요청 종료 후 다음 요청까지 최소 간격 |
| COLLECTION_RETRY_ROUNDS | 1 | 최초 처리 이후 추가 재시도 라운드, 0~3 |
| COLLECTION_RETRY_DELAY_SEC | 30 | 실패 라운드 사이 기본 대기, 추가 라운드마다 2배 |
| YFINANCE_RATE_LIMIT_COOLDOWN_SEC | 60 | Yahoo 제한 오류 공통 대기의 기본값 |

잠금은 프로세스 내부에만 적용된다. GitHub 수집 워크플로에는 concurrency 그룹을 추가해 중복 실행을 직렬화한다.
로컬에서는 `.env`, GitHub Actions에서는 같은 이름의 Repository variables로 설정한다. GitHub 변수 미설정 시 표의 기본값을 사용한다.
로컬 PC와 GitHub 등 다른 프로세스가 같은 폴더에 동시에 쓰는 것은 막지 못한다. 운영자는 수집 실행 주체를 하나로 유지한다.

## 검증과 적용

```powershell
python -m unittest discover -s tests -v
python scripts/benchmark_collection.py
```

회귀 테스트: 독립 Drive 연결 병렬 실행, 공유 연결 직렬화, 종목 중복 제거, 같은 종목 이력 보존, Yahoo 동시 요청 차단 및 공통 지연, 실패 종목만 재시도, 빈 응답 저장 차단, 모든 저장 완료 대기, 필수 자산군 실패 차단, UI 스레드 보호.
비교 스크립트는 12개 가상 종목과 고정된 네트워크 지연을 사용하며 순차/병렬 결과의 동일성을 검사한다. 실제 Yahoo/Drive 호출·저장·리포트 발행은 하지 않는다.
실제 운영 속도와 제한 오류 빈도는 다음 정기 수집의 단계별 로그로 판단한다. 문제가 있으면 `COLLECTION_WORKERS=1`로 되돌린다.
